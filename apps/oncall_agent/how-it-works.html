On-Call Triage Agent

An on-call agent triages incidents for four fictional services: up to two diagnostic probes, then one fix. Hidden causes make the cold keyword baseline wrong exactly where teaching happens — so any measured lift must come from memory. This app implements the complete documented learning loop: recall → capture IDs → act → objective verdict → record_outcome(entry_ids=…) → record_step_outcome per step → reflect(include_step_outcomes=True).

Pathway: Mubit-decided lessons record_outcome · record_step_outcome · reflect · recall All services & incidents are fictional

1 · The scenario

Probes: recent_deploys · dependency_health · infra_capacity. Fixes: rollback · restart_dependency · scale_out. The environment's truth table is hidden from the agent. The cold baseline (alphabetical probes + keyword fix) is wrong for T1–T3 and right for the controls C1–C3; held-out H1–H3 are paraphrases of the taught classes.

2 · The documented loop, as one agent

docs: capture

Recall, and capture the entry IDs

Lessons come back with IDs; the triage plan must cite the IDs it actually used — enforced in code.
docs: act

Act — probes, then one fix

A probe is informative only if it is the right one for this hidden cause; the environment — never the model — resolves the incident.
docs: objective verdict

Verdict

Resolved or not, plus which probes were informative. No self-grading anywhere.
docs: attribute

Attribute to exactly the entries used

record_outcome(reference_id, entry_ids=cited, signal=±1.0, idempotency_key=…) — multi-entry attribution; a retried call never double-counts; verified_in_production=False because this environment is synthetic.
docs: dense rewards

Step-level outcomes

One record_step_outcome per probe and per fix, with observational directive_hints that never name the hidden correct answer.
docs: distill

Mubit decides the lessons

advanced.reflect(include_step_outcomes=True) — the app authors no lesson; the validation gate decides what exists, and failing lessons return is_stale, filtered before the model sees them.

3 · Example data at each step

Recall + cited plan: 
in:  recall(query="On-call triage lessons for: Checkout failures jumped when we shipped …",
            entry_types=["lesson"], evidence_only=True)
out: [{"id": "f00d…", "content": "Checkout deploy-day error spikes are dependency flaps;
        restart the dependency instead of rolling back", "conditions": []}]

{"probes": ["dependency_health"], "fix": "restart_dependency",
 "lesson_ids": ["f00d…"], "reason": "Lesson matches checkout deploy-day error spikes",
 "baseline_fix": "rollback"}     // override cites what it used — or the run fails
Step outcomes — informative probe, uninformative probe, failed fix: 
record_step_outcome(step_id="exec/T1/probe/0", step_name="dependency_health",
  outcome="success", signal=1.0, directive_hint=None)
record_step_outcome(step_id="exec/T1/probe/1", step_name="recent_deploys",
  outcome="neutral", signal=0.0,
  directive_hint="this probe was uninformative for this incident; prefer probes that
                  were informative in past incidents of this kind")
record_step_outcome(step_id="exec/T1/fix", step_name="rollback",
  outcome="failure", signal=-1.0,
  directive_hint="rollback did not resolve this incident; reconsider the fixes that
                  past incidents of this service used")
Attribution — credit exactly the entries used: 
record_outcome(reference_id="f00d…", outcome="success", signal=1.0,
  entry_ids=["f00d…"],                          // multi-entry attribution
  idempotency_key="oncall-agent-v1:exec/T1",    // retries never double-count
  verified_in_production=False,                 // synthetic environment — honestly flagged
  rationale="Synthetic exec/T1: fix restart_dependency resolved the incident")
Every hint is observational. Directive hints describe what was observed, never the hidden correct fix or probe — the environment's truth table cannot leak into memory through the feedback path.

4 · Teaching runs the loop twice

Pass 1 — observe: teaching incidents run under the cold policy; each attempt is stored as raw evidence (remember(intent="fact") — nothing authors a fix preference) with per-step outcomes; reflect() produces the lessons. Pass 2 — apply + attribute: the same incidents run fresh; recall now returns lessons, the plan cites them, the environment delivers the verdict, and record_outcome credits the cited entries. Evaluation then compares OFF vs ON over six held-out incidents (paraphrases + controls) and fails explicitly if resolution does not improve.

5 · What this demonstrates

full attribution loop

The docs' pattern running verbatim: capture IDs → act → objective verdict → credit exactly those entries, with multi-entry attribution and idempotent outcomes.

process rewards

Per-probe and per-fix step outcomes with directive hints — dense signal for reflection, without leaking hidden truth.

no self-grading

The environment resolves incidents; the model never grades its own plan — the anti-pattern the docs warn about is structurally excluded.

Mubit-decided lessons

Raw facts in, reflection + validation gate out; is_stale entries never reach the model.
