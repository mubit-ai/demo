Care Coordination Agent

One agent coordinates care for one synthetic patient. The agent acts through 7 validated actions in a deterministic simulator. It learns patient-specific strategies from observed outcomes and 1 clinician correction. The lessons stay in Mubit across process restarts.

Current chart instructions always outrank stored lessons.

Pathway: deterministic (harness-owned SDK calls) Mubit: remember · recall · record_outcome All patients, charts and clinicians are synthetic

1 · Scenario

The simulator gives an 8-action budget. The agent must establish contact, explain chart-approved instructions, verify understanding, arrange transportation, and book the follow-up. The simulator hides patient-specific ground truth:

T1 · Contact

SMS gets no reply. Calls before 17:00 go to voicemail. A call at 17:00 or later establishes contact. This rule is patient-specific. It is not a general "SMS never works" rule.

T2 · Communication

The generic label-style text does not establish understanding. A failed comprehension check triggers 1 scripted clinician correction. The correction adds approved wording to the chart. Only that text, then a check, confirms understanding.

T3 · Coordination

Booking before transportation fails. Transportation first, then booking, succeeds.

2 · Flow

Every SDK call happens at a fixed code point in the harness. Lesson text comes only from lessons.py, and only from evidence that occurred. The runtime model chooses actions. It cannot write memory.

3 · The learning loop

owned by: harness

Capture

The agent acts. The simulator returns observed outcomes. Only data the agent was allowed to see can become evidence.
owned by: code

Distill

The code derives a candidate only when the full evidence pattern occurred. A contact lesson needs an SMS with no reply. Then it needs a successful call. The guidance stays conditional: "when no newer contact preference is available". The guidance never says "SMS never works".
owned by: code

Gate

The candidate must re-derive identically from the finished encounter. The provenance must match. The text must contain no treatment-like language and no hidden-simulator markers. Anything else is dropped.
owned by: Mubit

Promote

remember(intent="lesson", upsert_key=version:experiment:patient:category). The write is idempotent per patient and category. Re-teaching updates the slot. It does not create a duplicate.
owned by: harness

Inject

One recall runs before action 1. The list is frozen and SHA-256 hashed for the whole execution. The prompt policy fixes the authority order: current chart first, then current observations, then recalled lessons.
owned by: Mubit

Attribute

After the encounter, record_outcome reinforces exactly the lessons the agent cited. Success raises the evidence counters. Failure lowers them.

4 · Example data at each step

Field values come from the code and the scenarios. The patient is SYNTH-PT-0042. The channels are sms and phone_call. Each lesson becomes a hypervector in the medium. Recall is the SDM consensus read over it.

① Capture — decision in, outcome out (teaching encounter T1): 
// agent → simulator (pydantic-validated structured decision)
{"action": "outreach", "arguments": {"channel": "sms", "local_time": "09:00"},
 "rationale": "Chart lists sms and phone_call; try the lighter channel first.",
 "recalled_lesson_ids": []}
// simulator → observed outcome (the only ground truth the agent sees)
{"action": "outreach", "channel": "sms", "local_time": "09:00", "status": "no_response"}
② Distill — the derived lesson. The full pattern must occur: SMS no-reply, then a successful call at 17:00 or later: 
{"category": "contact_strategy", "patient_id": "SYNTH-PT-0042",
 "applicability": "when no newer contact preference is available for this patient",
 "guidance": "SMS receives no reply; a phone call at 17:00 or later establishes contact",
 "evidence_type": "observed_outcome",
 "evidence_summary": "T1: outreach(sms,09:00)→no_response; outreach(phone_call,17:05)→contact"}
③ Gate — the candidate must re-derive identically. The provenance must match. The text must contain no treatment-like language. Example of a rejection: a draft says "switch the evening dose". Medication wording is dropped before Mubit sees it.
④ Promote — the write: 
client.remember(
  content = "[experiment:cc-x] [demo:cc-memory-1]\n" + json.dumps({…lesson, experiment_id, source_encounter_id…}),
  intent="lesson", lesson_type="failure",          // learned from a failed SMS, not a correction
  lesson_scope="run", lesson_importance="high", agent_id="care-coordination-agent",
  upsert_key="cc-memory-1:cc-x:SYNTH-PT-0042:contact_strategy",   // re-teaching updates this slot
  wait=True)
⑤ Inject — recall before action 1. Only prompt-safe fields pass validation. The list is frozen and hashed for the whole execution: 
// in: recall(query="care coordination operational lessons for synthetic patient SYNTH-PT-0042",
//          entry_types=["lesson"], evidence_only=True)
// out: entry {"id": "5d3f…", "content": "[experiment:cc-x] [demo:cc-memory-1]\n{…}"}
// → after strict re-validation, the frozen snapshot the model receives:
[{"id": "5d3f…", "category": "contact_strategy", "applicability": "…",
  "guidance": "…", "evidence_summary": "…"}]      // snapshot SHA-256 identical across all 3 arms
⑥ Attribute — only cited lessons are reinforced: 
memory.record(reference_id="5d3f…", succeeded=True,
              rationale="E1: contact established on first call after 17:00")
// → client.record_outcome(reference_id="5d3f…", outcome="success", signal=1.0,
//                         verified_in_production=False)

In E2, the chart says "morning calls, 09:00–11:00". The stored lesson says "call at 17:00 or later". The agent calls at 09:30. The run scores PASS only when the current instruction wins.

Recall rejects entries that fail the marker, experiment, patient, category or schema checks. Reference IDs shown in the UI come from real Mubit recalls only. The app never fabricates an ID.

5 · Results

E1 — 3-arm comparison (fresh processes, frozen snapshot)

ArmMemoryIsolates
no_memoryemptycold behavior
full_memorythe exact frozen, hashed snapshotwhat the lessons change
ablated_contactcontact lessons removed, others intactper-category attribution: removing 1 lesson type must reverse the behavior it drove

Scoring is deterministic. There is no LLM judge. Evaluation writes nothing to Mubit.

E2 — current-preference override

The chart changes to "morning calls, 09:00–11:00". This conflicts with the stored after-17:00 lesson. The simulator rewards only the current instruction. The run reports PASS or FAIL on memory not overriding current truth.
