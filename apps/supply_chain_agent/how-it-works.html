Supply Chain Agent

Cedar Manufacturing (fictional) has a component shortage. One agent selects 1 recovery option. A deterministic simulator computes the consequences. Scripted operator feedback teaches the real tradeoff rules of the organization. Mubit stores the rules verbatim. Fresh processes recall them.

Pathway: deterministic (harness-owned SDK calls) Mubit: remember · recall · record_outcome All plants, inventory and feedback are fictional

1 · Scenario

Each incident gives logistics facts and 4 options: buy a substitute, wait for replenishment, transfer stock, or expedite freight. The agent starts with a public default: minimize combined downtime, then spend. The organization holds private preferences. The preferences exist only in the private evaluator and in the teaching feedback:

Replenishment

Accept up to 2 hours of receiving downtime and 0 donor downtime. Select the cheapest acceptable option first.

Firm orders

Permit 0 hours of receiving and donor downtime. Freight is approved to prevent a delay.

Fallback

No acceptable option: minimize combined downtime, then spend.

T1 and T2 are live teaching decisions with labeled operator feedback. E1–E3 are fresh evaluation cases. E3 is a firm order that must still expedite. E3 checks that the agent does not learn "always wait".

2 · The stored rules

Lesson 1 · applies_to: replenishment

Applicability: Cedar stock-replenishment orders only.

Guidance: Accept up to 2 hours of receiving-plant downtime with 0 donor downtime. Select the cheapest acceptable option, then the least downtime.

Exceptions: Do not apply this tolerance to firm customer orders. If no option meets the limits…

Lesson 2 · applies_to: firm

Applicability: Cedar firm customer orders only.

Guidance: Allow 0 hours of receiving and donor downtime. Among options that meet the limits, select the cheapest.

Exceptions: Do not extend this preference to stock replenishment…

The store path refuses any lesson that differs from the operator's confirmed lesson (if lesson != operator["confirmed_lesson"]: raise). No distillation step can invent a threshold. The full incident evidence is stored as a separate entry. That entry never enters a decision prompt.

4 · The learning loop

owned by: harness

Capture

The harness records the incident snapshot, the agent's live decision, and the simulator's consequences. Every teaching decision is live. Nothing is forced.
owned by: operator

Distill

Labeled operator feedback states the confirmed applicability, guidance, and exceptions. The lesson equals the operator's text. This is acquisition of explicit feedback. It is not autonomous discovery of a threshold.
owned by: code

Gate

The code checks byte equality against the confirmed lesson. Then it validates the schema. Storage fails loudly on any mismatch.
owned by: Mubit

Promote

remember(intent="lesson", upsert_key=demo_version:experiment:case). Re-teaching a case updates its slot. Version suffixes isolate v2 from v1 when the objective changes.
owned by: harness

Inject

Recall runs before each decision. Only 5 fields per lesson enter the prompt: id, source case, applies_to, applicability, guidance, exceptions. Full evidence stays in the trace. It never enters the decision context.
owned by: Mubit

Attribute

record_outcome reinforces only lessons the decision cited. Evaluation runs write nothing.
