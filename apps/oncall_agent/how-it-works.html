On-Call Triage Agent

An on-call agent triages incidents for 4 fictional services. The agent runs at most 2 diagnostic probes, then selects 1 fix. A hidden truth table makes the cold keyword baseline wrong on the 3 teaching classes and correct on the controls. Any lift must come from memory.

This app implements the complete documented loop: recall → capture entry IDs → act → objective verdict → record_outcome(entry_ids=…) → record_step_outcome per step → reflect(include_step_outcomes=True).

Pathway: Mubit-decided lessons record_outcome · record_step_outcome · reflect · recall All services and incidents are fictional

1 · Scenario

Probes: recent_deploys · dependency_health · infra_capacity. Fixes: rollback · restart_dependency · scale_out. The environment hides the truth table from the agent. The cold baseline uses alphabetical probes and a keyword fix. The baseline is wrong on T1–T3 and correct on C1–C3. H1–H3 are paraphrases of the taught classes.

2 · The documented loop

docs: capture

Recall, and capture the entry IDs

Lessons return with IDs. The triage plan must cite the IDs it used. Code enforces this rule.
docs: act

Act — probes, then 1 fix

A probe is informative only when it is the correct probe for the hidden cause. The environment resolves the incident. The model does not grade its own plan.
docs: objective verdict

Verdict

The environment reports resolved or not resolved. The environment also reports which probes were informative.
docs: attribute

Attribute to the entries used

record_outcome(reference_id, entry_ids=cited, signal=±1.0, idempotency_key=…). The call credits every contributing entry. A retried call does not count twice. verified_in_production=False because this environment is synthetic.
docs: dense rewards

Step-level outcomes

One record_step_outcome per probe and 1 for the fix. Each call carries an observational directive_hint. The hint states what was observed. The hint never names the hidden answer.
docs: distill

Mubit decides the lessons

advanced.reflect(include_step_outcomes=True). The app writes no lesson. The validation gate decides which lessons exist. A failing lesson returns marked is_stale. Recall filters it before the model sees it.

3 · Example data at each step

Recall + cited plan: 
in:  recall(query="On-call triage lessons for: Checkout failures jumped when we shipped …",
            entry_types=["lesson"], evidence_only=True)
out: [{"id": "f00d…", "content": "Checkout deploy-day error spikes are dependency flaps;
        restart the dependency instead of rolling back", "conditions": []}]

{"probes": ["dependency_health"], "fix": "restart_dependency",
 "lesson_ids": ["f00d…"], "reason": "Lesson matches checkout deploy-day error spikes",
 "baseline_fix": "rollback"}     // the override cites what it used — or the run fails
Step outcomes — informative probe, uninformative probe, failed fix: 
record_step_outcome(step_id="exec/T1/probe/0", step_name="dependency_health",
  outcome="success", signal=1.0, directive_hint=None)
record_step_outcome(step_id="exec/T1/probe/1", step_name="recent_deploys",
  outcome="neutral", signal=0.0,
  directive_hint="this probe was uninformative for this incident; prefer probes that
                  were informative in past incidents of this kind")
record_step_outcome(step_id="exec/T1/fix", step_name="rollback",
  outcome="failure", signal=-1.0,
  directive_hint="rollback did not resolve this incident; reconsider the fixes that
                  past incidents of this service used")
Attribution — credit the entries used: 
record_outcome(reference_id="f00d…", outcome="success", signal=1.0,
  entry_ids=["f00d…"],                          // multi-entry attribution
  idempotency_key="oncall-agent-v1:exec/T1",    // retries never double-count
  verified_in_production=False,                 // synthetic environment
  rationale="Synthetic exec/T1: fix restart_dependency resolved the incident")
Every hint is observational. A hint describes what was observed. A hint never names the hidden fix or the hidden probe. The truth table cannot leak into memory through the feedback path.

4 · Teaching runs the loop twice

Pass 1 — observe: the teaching incidents run under the cold policy. The app stores each attempt as raw evidence with remember(intent="fact"). The app writes no fix preference. Each step records an outcome. Then reflect() produces the lessons.

Pass 2 — apply and attribute: the same incidents run again in a fresh execution. Recall now returns lessons. The plan cites them. The environment delivers the verdict. record_outcome credits the cited entries.

Evaluation then compares OFF vs ON over 6 held-out incidents: 3 paraphrases and 3 controls. Resolution must improve, or the run fails explicitly.
