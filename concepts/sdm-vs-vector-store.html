Vector Store vs SDM — what the medium does

A vector store keeps rows and returns the nearest rows. SDM (Sparse Distributed Memory) keeps counters and returns the consensus of a neighborhood. The difference is not speed or accuracy on a single query. The difference is what the storage state itself can do over time.

Vector store: embedding rows + nearest-neighbor index SDM: 10,048-bit hypervectors + ±1 counters + consensus read

1 · The SDM write and read, in brief

WRITE — one pass, nothing is overwritten

1 · Encode

The text embedding passes through a fixed random projection. Each dimension takes the sign of its value. The result is 1 hypervector of 10,048 bits.

2 · Locate

A Hamming-distance search finds the top-K nearest hard locations. K is 50 in the recent tier and 500 in the permanent tier.

3 · Deposit

Each location holds 10,048 counters. The write adds +1 where the vector has a 1 bit. It adds −1 where the vector has a 0 bit. Counters saturate. Many memories share the same locations. Nothing is replaced.
READ — one pass, error-correcting

1 · Encode

The query text is encoded the same way, into the same bit space.

2 · Activate

The same top-K hard locations are activated.

3 · Vote

The counters are summed element by element. The sign of each sum forms the consensus pattern. Uncorrelated memories cancel in the sum. Similar memories add. The consensus is then used as an address to fetch the concrete stored entries.

Measured: a stored pattern re-queried with 1,072 flipped bits returns a consensus 0 bits from the original. Decay ×19/20 per cycle fades unused knowledge. Reinforced knowledge persists.

2 · Property by property

PropertyVector storeSDM medium
New experienceInserts a row. Near-duplicates and contradictions compete at retrieval with equal standing. Nothing in the store knows they conflict.A ±1 deposit. Memories superpose. A contradiction appears as weakened consensus. It is visible and resolvable.

ConfidenceRows carry no evidence weight. The application must add and maintain confidence columns.Counter magnitude and agreement encode evidence volume. 1 reinforcing write is weak; 10 are strong. Basin density gives a novelty map.

Path to weightsNone. To obtain a model of the rows, a system must train on them offline.Counters already behave like weights: additive updates, an inference-like read, regularization-like decay. A basin latent (1,256 bytes) is read directly off the counters and compiles to a LoRA adapter.
The one-line version: a vector store retrieves. The SDM medium learns. The difference is that the storage state of the medium already behaves like the parameters of a model.

3 · One dataset, two stores

Two lessons from the supply-chain demo, stored on day 1. Both concern Cedar orders, downtime, and money. Their guidance contradicts. On day 15, the organization reverses its objective. On day 30, a new process queries the store.

Vector store — day 1 → day 30

Day 1. Two rows enter. Both carry equal standing. The index does not know they disagree.

Day 15. The objective reverses. A third row enters. The two old rows keep full strength. Nothing retires them.

Day 30. The query returns whichever contradiction is nearest in embedding space. The result depends on the encoder, not on evidence. stale rows keep winning

SDM medium — day 1 → day 30

Day 1. Two lessons deposit into the same neighborhood. The contradiction shows as weakened consensus.

Day 15. The reversal is written into the same slot. Supersession retires the old guidance. The old entry stays queryable as history.

Day 30. The reinforced, operator-confirmed lesson dominates the vote. The decayed one contributes weakly. evidence decides

The router demo shows the same property on live data. The request "please send a duplicate invoice" shares the word "invoice" with a lesson learned from a billing-context incident. Keyword and embedding distance point at the wrong lesson. The lesson's conditions travel with it through memory. The router kept the baseline. Measured: 83.3% first-route accuracy, 0 wrong flips on the 3 controls.
