Data Analyst

An analyst answers questions over a synthetic warehouse. The schema never documents the business logic — "net revenue = bookings minus refunds", "active = ordered in 180 days" — and a mid-stream migration renames the refunds table. Both facts live only in Mubit.

Measured: cold analyst answers 2 of 6 questions (0 of 4 business questions). With memory: 6 of 6.

operator rules · schema notes with supersession · record_outcomeThe warehouse is an in-code fixture; verdicts are exact

1 · Scenario

QuestionClassCold analystWith memory
"How many orders in region EMEA?"basiccorrectcorrect
"Net revenue for customer acme?"businessgross bookings ✗bookings − refunds ✓
"How many refunds in August 2026?"driftqueries the renamed-away table ✗current table ✓
"How many active customers?"businesscounts everyone ✗180-day rule ✓

2 · Loop

Seed

Operator-confirmed business rules and schema note v1 are written once, upserted by slot. Re-writes supersede instead of duplicating.

Migrate

The warehouse renames refunds → refund_events. Schema note v2 is written over the same slot; the server marks v1 stale.

Answer

Each question becomes a query spec shaped by the recalled rules. Every answer is checked against the fixture; record_outcome grades the exact rules that were cited.

Contrast

The cold analyst has no rules: gross bookings instead of net, the dead table name, no active definition. Same warehouse, no memory.

3 · Example data
