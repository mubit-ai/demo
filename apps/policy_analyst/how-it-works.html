Policy Analyst

An analyst answers two kinds of questions about synthetic insurance policies: what the terms say today, and what they said when the claim was filed. The terms change mid-stream. A current-state-only memory answers the first class correctly and the second class wrong, every time. The bi-temporal read answers both exactly.

This demo needs no LLM. Every verdict is deterministic.

Patterns: bi-temporal · write-time reconciliation · user partitioning Mubit: remember · recall · record_outcome All policies, customers and claims are synthetic

1 · Scenario

The terms for one policy key diverge. Acme's water terms genuinely change on 2026-07-01. Acme's deductible is refined on 2026-05-01. Blobfax holds different terms the whole time:

CustomerKeyValidFact
Acmecoverage_water2026-01-01 → 06-30"Water damage is covered up to $50,000."
Acmecoverage_water2026-07-01 → open"Water damage is excluded; a separate flood rider is required."
Acmedeductible2026-01-01 → 04-30"The deductible is $500 per claim."
Acmedeductible2026-05-01 → open"…waived for preferred vendors."
Blobfaxcoverage_water2026-01-01 → open"Water damage is covered up to $25,000."

The held-out questions ask both classes. Q2 is the money question: "Acme filed a water-damage claim on 2026-04-10. What did the policy say then?" The answer that was true on that date is the one the store superseded 12 weeks ago.

2 · The loop

owned by: harness

Setup — write facts with valid time

Each fact is written with occurrence_time (when it became true, distinct from ingestion time), a validity window in metadata, the customer scope, and an upsert key per slot. The write-time reconciler supersedes or merges the old entry; the old entry stays queryable as history.
owned by: harness

Verify — idempotent retry

Setup recalls every fact and rewrites any that is not retrievable, with the same upsert key. The trace shows the retries.
owned by: Mubit

Two reads, one store

A plain query returns only live facts — the server hard-excludes superseded beliefs. A history-intent query ("What were the terms before the changes?") returns superseded facts as first-class evidence, marked is_stale. The read that matches the question is a server property, not prompt discipline.
owned by: harness

Adjudicate — close the loop

Two historical claims with known verdicts. The analyst cites the fact valid at the filing date; record_outcome credits it, in the customer's scope, with an idempotency key.
owned by: harness

Evaluate — two arms, no writes

The bi-temporal arm picks the read that matches the question. The current-state-only arm always reads the current snapshot — exactly how an overwrite-in-place memory answers.

3 · Example data at each step

Write — Acme water, new terms: 
client.remember(
  content="[fact:1] Water damage is excluded; a separate flood rider is required.",
  intent="fact", session_id=run_acme, user_id="acme",
  occurrence_time=ts("2026-07-01"),                    // when it became true
  metadata={"policy_key": "coverage_water", "valid_from": "2026-07-01", "valid_to": None},
  upsert_key="policy-analyst-v1:acme:coverage_water:2026-07-01", wait=True)
// the store marks the 2026-01-01 entry stale: superseded_by → this entry
Two reads of one store — Q2, claim filed 2026-04-10:

Current read (plain recall)

returns"Water damage is excluded; …" is_stale: false
historysuperseded fact excluded by the server
as answer to Q2wrong — that is today's terms

History read (history-intent query)

returns"Water damage is covered up to $50,000." is_stale: true
window filtervalid 2026-01-01 → 06-30 covers 04-10 ✓
as answer to Q2exact — the terms in force on the filing date
Attribute — the adjudication credits the fact it used: 
client.record_outcome(reference_id=fact_id, entry_ids=[fact_id],
  outcome="success", signal=1.0, user_id="acme", session_id=run_acme,
  idempotency_key="policy-analyst-v1:claim CLM-1042 …",
  rationale="claim CLM-1042 adjudicated covered under the terms valid on 2026-04-10")
Isolation is proven negatively. Blobfax's questions run in Blobfax's run and user scope. Acme's exclusion never reaches a Blobfax answer — Q5 expects $25,000 coverage, and both arms answer it correctly.

4 · Results (committed live traces)

ArmCurrent classAs-of classTotal
Bi-temporal read3 / 33 / 36 / 6
Current-state-only memory3 / 30 / 33 / 6
One line tells the whole story. Both arms answer every "today" question correctly. Every "when the claim was filed" question separates them: the current-state-only memory is wrong on all three — it answers from terms that did not exist when the claim was filed. The bi-temporal read is exact on all three, reading the superseded entry the store kept as history. Cross-customer leaks: 0.
